## 1. 项目定位

Dianguard 是一款面向中国大陆的**个人级地震预警 Android 应用**。它实时订阅国家级地震预警（EEW）数据流，在破坏性横波（S 波）抵达前的数秒至数十秒窗口内，以**全屏锁屏告警 + 最大音量真实语音 + 震动**的组合强制唤醒用户，争取逃生时间。

设计上它不是一个"看地震新闻的 App"，而是一台**长期通电常驻、以可用性为第一目标的专用告警终端**——典型部署方式是把一台闲置旧手机插上电源放在客厅或卧室。因此本项目的全部工程取舍都围绕三条原则：

| 原则 | 具体体现 |
|------|---------|
| **先到先发** | 首报烈度达标立即全屏告警，**不等任何第二源、不做融合窗口**——灾害中每一秒都是避险时间 |
| **官方优先** | ICL（减灾所官方预警网）与 CENC（中国地震台网官网目录）为最高优先级；第三方转发源仅作补充与兜底 |
| **长期稳定** | 前台服务 + WakeLock 周期续期 + 事件状态 TTL 淘汰 + 服务僵尸态防护，保证数月不重启场景下可靠常驻 |

> v1.4.3 说明：v1.3.x 的「多源融合决策引擎（EewFusion）」已**整体移除**。实测它以"等待第二源"换取抗误报，代价是首报延迟 1.5 秒以上——对生命安全场景不划算。现在的策略是**先到先发 + 多层去重**：单源报错由跨机构事件归并与报文序号保护兜底，速度不再为算法让路。

## 3. 系统架构

### 3.1 数据流

Dianguard 采用"**多路实时源 → 事件归并 → 分区烈度衰减 → 即时响应**"四层架构。底层物理模型基于 GB 18306-2015《中国地震动参数区划图》，告警决策为**先到先发**。

```
┌─ 实时数据源层 ─────────────────────────────────────────────────┐
│   ICL 减灾所官方 ──── HTTP 1s 增量轮询（mobile-new.chinaeew.cn）│
│   中国地震台网 CENC ─┐                                        │
│   四川省地震局  SC  ─┤  WebSocket 秒级推送                     │
│   重庆市地震局  CQ  ─┤  （Wolfx 镜像 · ws-api.wolfx.jp）        │
│   台湾地震测报  CWA ─┘                                        │
│   ↓ 任一 WS 故障 ≥2 次                                         │
│   同机构 HTTP 降级轮询（4s，api.wolfx.jp/{src}_eew.json）       │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 解析与归并层 ────────────────────────────────────────────────┐
│   parseEew / parseExternalEew / parseIclEew / parsePodrisEew  │
│   异构报文归一化 → 官方 eventId 事件归并 → 报序保护 → 报数去重   │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 物理模型层 ── GeoUtils ──────────────────────────────────────┐
│   GB 18306-2015 六分区短轴衰减 · 边界防抖 · 0.5σ 安全边际        │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 响应层 ── EewAlertManager → AlertActivity（先到先发）─────────┐
│   首报烈度达标 → 立即全屏锁屏 · 四级真实语音 · 空间震源距倒计时   │
│   修正报 → 立即刷新震级/烈度/报数/倒计时（上修下修均更新）        │
└───────────────────────────────────────────────────────────────┘

┌─ 旁路 1：CENC 官方目录（历史/回放权威源，最高优先级）───────────┐
│   https://www.ceic.ac.cn/data/data.json（近 8 个月官方目录）    │
├─ 旁路 2：备用探测源（主链路全断时激活，仅历史记录）─────────────┤
│   USGS FDSN + Wolfx HTTP + EMSC FDSN，30s 轮询                 │
└───────────────────────────────────────────────────────────────┘
```

| 源 | 机构 | 协议 | 属性 | 说明 |
|------|------|------|------|------|
| **ICL** | 成都高新减灾研究所（中国地震预警网） | **HTTP 1s 增量轮询** | 🏷️ 官方直连 | 官方预警发布机构，域名完全独立；start_at 增量过滤使 1s 轮询近零流量，平均接收延迟约 0.5s |
| **CENC** | 中国地震台网 | WebSocket 推送 | 转发 | 全国主源 |
| **SC** | 四川省地震局 | WebSocket 推送 | 转发 | 西南地区互证 |
| **CQ** | 重庆市地震局 | WebSocket 推送 | 转发 | 西南地区互证 |
| **CWA** | 中国台湾地震测报中心 | WebSocket 推送 | 转发 | 覆盖台湾海峡震源，补足东南沿海离岸地震的延迟与欠报 |
| BeeCLD | 用户自注册（可选） | WebSocket | 用户自备 Key | App **不内置密钥**，需用户自行注册填写 |

> ⚠️ **单点风险与自动降级**：CENC/SC/CQ/CWA 四路均经 Wolfx 镜像分发、共用 `ws-api.wolfx.jp` 网关。该网关故障（如 503）时：
> ① 每路自动启用**同机构 HTTP 降级轮询**（4s，实测可用），主页显示「HTTP降级·接收中」而非惊悚的「源异常」；
> ② ICL 官方源（独立域名）始终并行运行，预警不中断；
> ③ 全部失效时 30s 后启用备用探测源。三层递进，官方直连源始终可用。

**官方目录源（历史 / 回放权威数据，最高优先级）**

| 源 | 机构 | 覆盖 | 说明 |
|------|------|------|------|
| **CENC 官方目录** | 中国地震台网（www.ceic.ac.cn） | 近 8 个月 / 795 条 | 官网数据接口，HTTPS 免鉴权；历史与回放同步的**第一优先级**，wolfx 镜像按官方 eventId 去重 |

**备用探测源（震后速报，不触发全屏告警）**

| 源 | 协议 | 说明 |
|------|------|------|
| USGS FDSN | HTTP 30s | 真正的非 Wolfx 独立源，自带 2 小时长周期去重 |
| Wolfx HTTP | HTTP 30s | 主链路 WS 断开时的同源兜底 |
| EMSC FDSN | HTTP 30s | 独立第三源 |

> 备用源属"震后速报"，从发震到进入目录通常已数分钟，**预警时效已过**，故仅用于历史记录与状态展示。

## 4. 告警决策与核心算法

### 4.1 先到先发（v1.4.3 核心决策）

```
任一源报文到达
        │
        ▼
本地预估烈度 ≥ 阈值(3°/2°/4°)？
        │
   是 ──┴── 否（仅通知栏提示 + 记录历史）
   ▼
立即全屏锁屏弹出（首报即触发，不等第二源、无融合窗口）
        │
        ▼
后续修正报到达 → 立即刷新：震级 / 烈度 / 报数 / 倒计时
（官方上修、下修均实时更新页面；跨机构报文按事件归并联动）
```

**为什么移除融合引擎**：v1.3.x 的融合设计是"首报进入 1.5s 窗口，等第二源交叉验证后再决策"。实测这意味着**每一场地震的首次告警都被人为推迟 1.5 秒以上**——在预警盲区边缘，这 1.5 秒就是避险时间。v1.4.3 起改为**先到先发**：误报风险由事件归并去重与官方源优先承接，速度不再为算法让路。

### 4.2 GB 18306-2015 分区烈度衰减模型

放弃全国单一公式，改用第五代地震区划图的六分区短轴衰减模型（含震中坐标自动分区选择）：

```
I = A + B·M + C·lg(R + R₀) + 0.5σ
```

| 分区 | 覆盖范围 | 短轴系数 (A, B, C, R₀) | σ |
|------|---------|----------------------|-----|
| 川滇西南 | 云南全境 + 川西 | 2.941, 1.363, −1.494, 7 | 0.67 |
| 四川盆地 | 成都 / 重庆周边 | 3.456, 1.280, −1.608, 7 | 0.61 |
| 青藏区 | 青藏高原 + 甘南 | 3.368, 1.275, −3.312, 9 | 0.66 |
| 新疆区 | 天山南北 | 3.611, 1.435, −3.848, 13 | 0.59 |
| 东部强震区 | 华北 + 东北 | 3.659, 1.363, −3.541, 13 | 0.58 |
| 中强地震区 | 华南 + 华中 | 3.944, 1.071, −2.845, 7 | 0.52 |

**关键特性**

- **深源修正**：云南深源地震区（depth > 60 km）启用郁曙君 1993 特殊公式
- **边界防抖**：震中距分区边界 < 15 km 时双区并行计算取 MAX
- **安全边际**：触发阈值采用 +0.5σ 偏上分位数，宁可高报不低报
- **倒计时修正**：S 波到达时间使用**空间震源距** √(震中距² + 深度²)，深源地震不倒计时假警报
- **剩余时间修正**：倒计时扣除「发震 → 收到报文」的官方延迟，不再把已流逝时间重复计入
- **无效值拦截**：M < 3.0 或 R < 0 直接返回 −1，跳过触发

### 4.3 告警呈现（对齐 ICL / 国家标准）

```
顶部：预警等级横幅（红色预警 / 橙色预警 / 黄色预警 / 蓝色预警）
中部：大号倒计时 + 「地震波将于 X 秒后到达」提示横幅（每秒刷新）
      震中地点 · X.X级地震 · 震源深度 · 距您 X 公里
      分级避险指引（一句话行动指令，随等级变色）
归零：「地震波已抵达 · 请立即避险」+ 警报循环 + 震动
```

> **两套分级标准并存**（对齐王暾团队"地震预警"App 设计）：
> **历史列表颜色 = 震级**（红 ≥6.0 / 橙 5.0–5.9 / 黄 3.0–4.9 / 蓝 <3.0，代表地震本身有多强）；
> **倒计时弹窗颜色 = 烈度**（红 ≥7° / 橙 5–6° / 黄 3–4° / 蓝 <3°，代表地震波传到你家时该怎么避险）。
> 二者服务于不同的认知目的，**不可混用**。

## 5. 可靠性工程

面向"数月连续运行不重启"的部署场景，本项目在工程层面做了以下保障：

| 机制 | 实现 |
|------|------|
| **进程存活** | 前台服务 + `START_STICKY` 被杀后自动重建；僵尸态防护（开关已关时自停，杜绝"假守护"） |
| **CPU 保活** | `PowerManager.WakeLock` 持有 + 周期性续期，避免系统超时自动释放 |
| **开机恢复** | `BootCompletedReceiver` 重启后自动恢复监听 |
| **前台自愈** | 主页回到前台检测「开关已开但服务未运行」→ 自动重新拉起 |
| **Android 15+ 6h 超时** | dataSync 前台服务超时后自动以 `specialUse` 类型续期，7×24 常驻不失联 |
| **长连接心跳** | OkHttp `pingInterval 20s`；`readTimeout 60s` 避免误判断连 |
| **断线重连 + HTTP 降级** | WS 故障 ≥2 次自动启用同机构 HTTP 轮询（4s），恢复后自动切回；三层递进兜底 |
| **跨源去重** | 10 分钟去重窗口（官方 eventId 事件归并），同事件多源多报不重复弹窗；报序保护防旧报倒灌 |
| **刷新抑制** | 修正报需震级 Δ≥0.3 / 烈度 Δ≥0.5 / ETA Δ>3s 才刷新 UI，3 秒防抖，不打断倒计时与语音 |
| **内存有界** | 事件状态表 30 分钟 TTL 淘汰；逐报快照上限 100 条 |
| **降级逃生口** | 仅在**证书校验类异常**时触发；普通 HTTP 错误（如 503）**不会**导致证书固定被绕过 |
| **运行时自检** | `SelfCheck` 检查悬浮窗 / 通知 / 电池优化 / 位置权限，异常项在首页显式提示 |

### 界面与交互

- **iOS 风格视觉语言**：卡片式布局、系统级配色语义、统一圆角与留白
- **三 Tab 结构**：首页（监听状态 / 数据源 / 自检）· 历史（速报列表 + 官方徽标）· 设置

## 6. 安全架构

### 6.1 证书固定（Certificate Pinning）

预警 / 历史数据链路的关键域名实施 **SPKI 证书固定**（leaf + 中间 CA 双 pin），防中间人注入**虚假地震预警**：

| 域名 | 用途 | 固定方式 |
|------|------|---------|
| `ws-api.wolfx.jp` | 实时 EEW（CENC/SC/CQ/CWA） | leaf + Google Trust Services WE1 |
| `api.wolfx.jp` | 历史速报 / HTTP 降级 | leaf + Google Trust Services WE1 |
| `mobile-new.chinaeew.cn` | ICL 官方轮询源 | leaf + WoTrus RSA DV SSL CA 2 |
| `earthquake.usgs.gov` | 备用源 | leaf + DigiCert Global G2 |
| `www.seismicportal.eu` | 备用源 | leaf + Let's Encrypt YR2 |

> CENC 官方目录（www.ceic.ac.cn）与逆地理编码走系统信任链 HTTPS（均有效公共 CA 证书）。
> 即使攻击者控制网络层，也无法用伪 CA 证书冒充数据源。leaf 轮换由中间 CA pin 兜底，不中断预警链路。

### 6.2 防伪造 / 防重放

- **传输层**：证书固定防中间人（见 6.1）
- **归并层**：跨机构事件归并（发震时刻 ±90s 且震中距 ≤40km 视为同一地震），单源伪造报文与官方/其他机构数据显著不一致时无法形成独立事件
- **序号层**：同源 eventId 报数只增不减，旧报倒灌与同报数重复报文直接丢弃
- **去重层**：10 分钟跨源去重窗口，同事件多报不重复弹窗

### 6.3 组件暴露面

| 项 | 配置 |
|------|------|

## 9. 预警知识库（官方标准依据）

### 9.1 预警五要素

地震预警利用**电波比地震波快**的原理，在破坏性地震波（S 波）到达前向用户推送预警。预警信息包含五要素：

| 要素 | 说明 |
|------|------|
| 发震时刻 | 地震发生的时刻（由预警系统自动测定） |
| 震中位置 | 震源在地表的投影位置 |
| 预警震级 | 系统自动分析产生的震级，会随监测信息增加而更新（应用内展示为「X.X 级地震」） |
| 预估烈度 | 地震对**您所在区域**的影响和破坏程度（应用内按此分级配色） |
| 预警时间 | 破坏性地震波即将到达的倒计时（应用内全屏倒计时） |

> 一次地震只有一个震级，但在不同地区烈度不同（如同炸弹的炸药量与各处破坏程度的关系）。示例：常熟–太仓 5.1 级地震，太仓沙溪镇烈度 6 度、苏州 4 度、无锡 3 度——震级全境相同，烈度因地而异。

### 9.2 震级分类（GB/T 17742-2020 依据）

| 分类 | 震级范围 | 特征 |
|------|---------|------|
| 弱震 | < 3 级 | 震源不浅时一般不易察觉 |
| 有感地震 | 3 – 4.5 级 | 人能感觉到，一般不造成破坏 |
| 中强震 | 4.5 – 6 级 | 可造成破坏（轻重与震源深度、震中距有关） |
| 强震 | ≥ 6 级 | 破坏性强；≥ 8 级又称巨大地震 |

> 震级每相差 1.0 级，能量相差约 30 倍；相差 2.0 级，能量相差约 900 倍。

### 9.3 地震烈度 12 级（《中国地震烈度表》GB/T 17742-2020 节选）

| 烈度 | 人的感觉 / 破坏情况 |
|------|---------------------|
| Ⅰ–Ⅱ（1–2）| 无感；室内个别静止中的人有感觉 |
| Ⅲ–Ⅳ（3–4）| 室内多数人有感；悬挂物明显摆动，器皿作响 |
| Ⅴ（5）| 多数人睡梦中惊醒；悬挂物大幅度晃动，水从盛满容器溢出 |
| Ⅵ（6）| 多数人站立不稳、惊逃户外；少数轻家具移动，河岸软土裂缝 |
| Ⅶ（7）| 物品从架子掉落、家具倾倒；河岸塌方，地裂缝较多 |
| Ⅷ（8）| 多数人摇晃颠簸、行走困难；除重家具外多数物品倾倒 |
| Ⅸ（9）| 行动的人摔倒；供水管道广泛破坏，大范围停水，滑坡塌方常见 |
| Ⅹ（10）| 骑自行车的人摔倒；山崩和地震断裂出现 |
| Ⅺ–Ⅻ（11–12）| 地震断裂延续很大，大量山崩滑坡，地面剧烈变化、山河改观 |

> 应用内预警等级即按此标准映射：**红 ≥ 7°（灾害性）｜橙 5–6°（灾害性）｜黄 3–4°（告知性）｜蓝 < 3°（告知性）**。高楼层有放大效应，震感可能更明显。
