## 1. 项目定位

Dianguard 是一款面向中国大陆的**个人级地震预警 Android 应用**。它实时订阅国家级地震预警（EEW）数据流，在破坏性横波（S 波）抵达前的数秒至数十秒窗口内，以**全屏锁屏告警 + 最大音量真实语音 + 震动**的组合强制唤醒用户，争取逃生时间。

设计上它不是一个"看地震新闻的 App"，而是一台**长期通电常驻、以可用性为第一目标的专用告警终端**——典型部署方式是把一台闲置旧手机插上电源放在客厅或卧室。因此本项目的全部工程取舍都围绕三条原则：

| 原则 | 具体体现 |
|------|---------|
| **可用性优先** | 五路实时源并行订阅，任一可达即可预警；主链路全断时仍有独立备用探测链路 |
| **误报可控** | 多源交叉验证 + 加权中位数抗异常值 + 震级系统性偏差校准，单源报错不会独自触发高等级告警 |
| **长期稳定** | 前台服务 + WakeLock 周期续期 + 事件状态 TTL 淘汰，保证数月不重启场景下内存有界 |

## 3. 系统架构

### 3.1 数据流

Dianguard 采用"**多路实时源 → 融合决策 → 分区烈度衰减 → 渐进式响应**"四层架构。底层物理模型基于 GB 18306-2015《中国地震动参数区划图》，上层决策由自研多源融合引擎驱动。

```
┌─ 实时数据源层（五路并行，任一可达即可预警）────────────────────┐
│   中国地震台网 CENC ─┐                                        │
│   四川省地震局  SC  ─┤  WebSocket 秒级推送                     │
│   重庆市地震局  CQ  ─┤  （Wolfx 镜像 · ws-api.wolfx.jp）        │
│   台湾地震测报  CWA ─┘                                        │
│   ICL 减灾所官方 ──── HTTP 3s 轮询（mobile-new.chinaeew.cn）    │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 解析层 ──────────────────────────────────────────────────────┐
│   parseEew / parseExternalEew / parseIclEew / parsePodrisEew  │
│   异构报文归一化 → 统一 Eew 数据模型（含字段拼写差异兼容）        │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 融合决策层 ── EewFusion ─────────────────────────────────────┐
│   动态融合窗 · 加权中位数 · 震级校准 · 坐标质心选优 · 版本隔离    │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 物理模型层 ── GeoUtils ──────────────────────────────────────┐
│   GB 18306-2015 六分区短轴衰减 · 边界防抖 · 0.5σ 安全边际        │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌─ 响应层 ── EewAlertManager → AlertActivity ───────────────────┐
│   烈度阈值判定 → 全屏锁屏 · 四级真实语音 · 空间震源距倒计时       │
└───────────────────────────────────────────────────────────────┘

┌─ 旁路：备用探测源（主链路全断时激活，仅历史记录，不触发告警）──┐
│   USGS FDSN + Wolfx HTTP + EMSC FDSN，30s 轮询                 │
└───────────────────────────────────────────────────────────────┘
```

**备用探测源（震后速报，不触发全屏告警）**

| 源 | 协议 | 说明 |
|------|------|------|
| USGS FDSN | HTTP 30s | 真正的非 Wolfx 独立源，自带 2 小时长周期去重 |
| Wolfx HTTP | HTTP 30s | 主链路 WS 断开时的同源兜底 |
| EMSC FDSN | HTTP 30s | 独立第三源 |

> 备用源属"震后速报"，从发震到进入目录通常已数分钟，**预警时效已过**，故仅用于历史记录与状态展示。

## 4. 核心算法

### 4.1 多源融合决策引擎

融合引擎在**动态融合窗口**内收集多源报文，通过**多源交叉验证 + 抗异常值融合**降低单源误报风险，并具备震级系统性偏差校准、坐标防抖、按事件版本隔离、超时强制输出等工程保障。

| 能力 | 说明 |
|------|------|
| 加权中位数融合 | 取代简单加权平均，从根本上抗单源异常值污染 |
| 动态融合窗口 | 多源活跃时自动缩短窗口抢预警时间，单源时保守等待第二源 |
| 震级校准 | 内置离线预训练画像，按「源 × 震级区间」修正各源系统性偏差，修正量钳制 ±0.5 级 |
| 动态趋势积分 | 按各源相对共识的偏移趋势动态调权 |
| 校准-权重协同 | 源权重 = 可靠性权重 × 稳定性因子，历史波动大的源自动降权 |
| 初报/终报分轨 | 初报与终报分别建模，避免混合污染预警第一时间的判断 |
| 坐标质心选优 | 取权重最高源的原始坐标，**严禁加权平均**（平均会产生地理上不存在的震中） |
| 坐标死区 | 偏移小于阈值时沿用旧坐标，防止高频震荡 |
| 版本隔离 | 按事件独立递增版本号，修正幅度过大时强制推送更新 |
| 状态 TTL 淘汰 | 事件级状态表 30 分钟无活动即淘汰，保证常驻运行下内存有界 |

> ℹ️ 本开源仓库包含融合引擎的**兼容精简实现**（加权平均 + 坐标选优 + 去重）；完整版引擎及其校准模块为**闭源专有**（详见 [§10 许可声明](#10-许可声明)），不随本仓库分发。上表描述的是发布版 APK 所搭载的完整版能力。

### 4.2 GB 18306-2015 分区烈度衰减模型

放弃全国单一公式，改用第五代地震区划图的六分区短轴衰减模型（含震中坐标自动分区选择）：

```
I = A + B·M + C·lg(R + R₀) + 0.5σ
```

| 分区 | 覆盖范围 | 短轴系数 (A, B, C, R₀) | σ |
|------|---------|----------------------|-----|
| 川滇西南 | 云南全境 + 川西 | 2.941, 1.363, −1.494, 7 | 0.67 |
| 四川盆地 | 成都 / 重庆周边 | 3.456, 1.280, −1.608, 7 | 0.61 |
| 青藏区 | 青藏高原 + 甘南 | 3.368, 1.275, −3.312, 9 | 0.66 |
| 新疆区 | 天山南北 | 3.611, 1.435, −3.848, 13 | 0.59 |
| 东部强震区 | 华北 + 东北 | 3.659, 1.363, −3.541, 13 | 0.58 |
| 中强地震区 | 华南 + 华中 | 3.944, 1.071, −2.845, 7 | 0.52 |

**关键特性**

- **深源修正**：云南深源地震区（depth > 60 km）启用郁曙君 1993 特殊公式
- **边界防抖**：震中距分区边界 < 15 km 时双区并行计算取 MAX
- **安全边际**：触发阈值采用 +0.5σ 偏上分位数，宁可高报不低报
- **倒计时修正**：S 波到达时间使用**空间震源距** √(震中距² + 深度²)，深源地震不倒计时假警报
- **无效值拦截**：M < 3.0 或 R < 0 直接返回 −1，跳过触发

### 4.3 告警触发与响应

```
本地预估烈度 ≥ 阈值(3°/2°/4°) ──→ 融合引擎决策 ──→ 全屏锁屏弹出
        │
        ▼
  倒计时弹窗等级（按【用户所在地预估烈度】，中国地震局官方标准）：
    Ⅰ级红 ≥7°（灾害性）· Ⅱ级橙 5–6°（灾害性）
    Ⅲ级黄 3–4°（告知性）· Ⅳ级蓝 <3°（告知性）
        │
        ▼
  三段式真实语音（大陆预警录音，非 TTS）：
    短语循环 → 逐秒倒计时 → 警报循环
        │
        ▼
  归零后显示避险指引：「趴下、掩护、抓牢 · 远离玻璃窗与重物」
```

> **两套分级标准并存**（对齐王暾团队"地震预警"App 设计）：
> **历史列表颜色 = 震级**（红 ≥6.0 / 橙 5.0–5.9 / 黄 3.0–4.9 / 蓝 <3.0，代表地震本身有多强）；
> **倒计时弹窗颜色 = 烈度**（红 ≥7° / 橙 5–6° / 黄 3–4° / 蓝 <3°，代表地震波传到你家时该怎么避险）。
> 二者服务于不同的认知目的，**不可混用**。

## 5. 可靠性工程

面向"数月连续运行不重启"的部署场景，本项目在工程层面做了以下保障：

| 机制 | 实现 |
|------|------|
| **进程存活** | 前台服务 + `START_STICKY` 被杀后自动重建；`FOREGROUND_SERVICE_IMMEDIATE` 立即显示通知 |
| **CPU 保活** | `PowerManager.WakeLock` 持有 + 周期性续期，避免系统超时自动释放 |
| **开机恢复** | `BootCompletedReceiver` 重启后自动恢复监听 |
| **长连接心跳** | OkHttp `pingInterval 20s` 保证长连接持续收到心跳帧；`readTimeout 60s` 远大于心跳间隔，避免"长时间无数据"误判断连 |
| **断线重连** | 连接管理器统一编排 `reconnectAll()`；旧连接回调带废弃标记防守，避免过期回调污染状态 |
| **跨源去重** | 10 分钟去重窗口（`quakeKey` 量化归并），同一事件多源多报不重复弹窗；备用源另用 2 小时长周期窗口 |
| **内存有界** | 融合引擎事件状态表 30 分钟 TTL 淘汰（v1.3.2 修复项） |
| **降级逃生口** | 仅在**证书校验类异常**时触发；普通 HTTP 错误（如 503）**不会**导致证书固定被绕过 |
| **运行时自检** | `SelfCheck` 检查悬浮窗 / 通知 / 电池优化 / 位置权限，异常项在首页显式提示 |

### 界面与交互

- **iOS 风格视觉语言**：卡片式布局、系统级配色语义、统一圆角与留白
- **三 Tab 结构**：首页（监听状态 / 数据源 / 自检）· 历史（速报列表）· 设置
- **统一转场动效**：页面淡入 + 轻微缩放、Tab 淡入淡出、更多设置右侧滑入、历史列表逐项级联入场
- **数据源状态可视化**：绿色「已连接」/ 橙色「源异常·\<HTTP 码\>」/ 灰色「连接中…」，服务端故障与本地网络问题一眼可辨，源恢复后自动转回绿色

> ⚠️ **告警页刻意不加任何动画**。全屏告警是生命安全场景，任何入场动效都是对逃生时间的浪费——保持瞬时弹出。

## 6. 安全架构

### 6.1 证书固定（Certificate Pinning）

所有预警 / 历史数据链路均实施 **SPKI 证书固定**（leaf + 中间 CA 双 pin），防中间人注入**虚假地震预警**：

| 域名 | 用途 | 固定方式 |
|------|------|---------|
| `ws-api.wolfx.jp` | 实时 EEW（CENC/SC/CQ/CWA） | leaf + Google Trust Services WE1 |
| `api.wolfx.jp` | 历史速报主源 | leaf + Google Trust Services WE1 |
| `mobile-new.chinaeew.cn` | ICL 官方轮询源 | leaf + WoTrus RSA DV SSL CA 2 |
| `earthquake.usgs.gov` | 备用源 | leaf + DigiCert Global G2 |
| `www.seismicportal.eu` | 备用源 | leaf + Let's Encrypt YR2 |
| `api.bigdatacloud.net` | 逆地理编码 | leaf + Thawte TLS RSA CA G1 |

> 即使攻击者控制网络层，也无法用伪 CA 证书冒充数据源。leaf 轮换由中间 CA pin 兜底，不中断预警链路。

### 6.2 防伪造 / 防重放

- **传输层**：证书固定防中间人（见 6.1）
- **应用层**：多源融合交叉验证——单源伪造报文会被抗异常值机制抑制，双源以上一致才触发高等级告警
- **去重层**：10 分钟跨源去重窗口，同事件多报不重复弹窗

### 6.3 组件暴露面

| 项 | 配置 |
|------|------|
| 导出组件 | 仅 Launcher `MainActivity`；其余 Activity / Service / Receiver 全部 `exported=false` |
| FileProvider | `exported=false` + `grantUriPermissions`，路径白名单受控 |
| 数据备份 | `allowBackup=false`，防止本地配置被 adb 备份提取 |
| 明文流量 | `usesCleartextTraffic=false`，全链路 HTTPS / WSS |

### 6.4 密钥管理

- 签名密钥 `*.jks` / `local.properties` 均已 `.gitignore` 忽略，**从未进入版本库**
- 签名密码支持环境变量注入（`DIANGUARD_STORE_PASSWORD` 等），CI / 发布时无需落盘明文
- 崩溃日志 `crash.txt` 坐标自动脱敏
- App **不内置任何第三方 API 密钥**；可选源的 Key 由用户自行注册填写，仅存本机

## 7. 隐私与权限

### 7.1 隐私承诺

- 位置坐标**仅保存在本机** SharedPreferences，除逆地理编码（获取地名）外不向任何服务器发送
- 无埋点、无统计 SDK、无崩溃上报服务、无广告
- 历史记录以 JSON 存本地，不引入数据库，卸载即清除

### 7.2 权限清单

| 权限 | 用途 |

## 9. 预警知识库（官方标准依据）

### 9.1 预警五要素

地震预警利用**电波比地震波快**的原理，在破坏性地震波（S 波）到达前向用户推送预警。预警信息包含五要素：

| 要素 | 说明 |
|------|------|
| 发震时刻 | 地震发生的时刻（由预警系统自动测定） |
| 震中位置 | 震源在地表的投影位置 |
| 预警震级 | 系统自动分析产生的震级，会随监测信息增加而更新（应用内展示为「X.X 级地震」） |
| 预估烈度 | 地震对**您所在区域**的影响和破坏程度（应用内按此分级配色） |
| 预警时间 | 破坏性地震波即将到达的倒计时（应用内全屏倒计时） |

> 一次地震只有一个震级，但在不同地区烈度不同（如同炸弹的炸药量与各处破坏程度的关系）。示例：常熟–太仓 5.1 级地震，太仓沙溪镇烈度 6 度、苏州 4 度、无锡 3 度——震级全境相同，烈度因地而异。

### 9.2 震级分类（GB/T 17742-2020 依据）

| 分类 | 震级范围 | 特征 |
|------|---------|------|
| 弱震 | < 3 级 | 震源不浅时一般不易察觉 |
| 有感地震 | 3 – 4.5 级 | 人能感觉到，一般不造成破坏 |
| 中强震 | 4.5 – 6 级 | 可造成破坏（轻重与震源深度、震中距有关） |
| 强震 | ≥ 6 级 | 破坏性强；≥ 8 级又称巨大地震 |

> 震级每相差 1.0 级，能量相差约 30 倍；相差 2.0 级，能量相差约 900 倍。

### 9.3 地震烈度 12 级（《中国地震烈度表》GB/T 17742-2020 节选）

| 烈度 | 人的感觉 / 破坏情况 |
|------|---------------------|
| Ⅰ–Ⅱ（1–2）| 无感；室内个别静止中的人有感觉 |
| Ⅲ–Ⅳ（3–4）| 室内多数人有感；悬挂物明显摆动，器皿作响 |
| Ⅴ（5）| 多数人睡梦中惊醒；悬挂物大幅度晃动，水从盛满容器溢出 |
| Ⅵ（6）| 多数人站立不稳、惊逃户外；少数轻家具移动，河岸软土裂缝 |
| Ⅶ（7）| 物品从架子掉落、家具倾倒；河岸塌方，地裂缝较多 |
| Ⅷ（8）| 多数人摇晃颠簸、行走困难；除重家具外多数物品倾倒 |
| Ⅸ（9）| 行动的人摔倒；供水管道广泛破坏，大范围停水，滑坡塌方常见 |
| Ⅹ（10）| 骑自行车的人摔倒；山崩和地震断裂出现 |
| Ⅺ–Ⅻ（11–12）| 地震断裂延续很大，大量山崩滑坡，地面剧烈变化、山河改观 |

> 应用内预警等级即按此标准映射：**红 ≥ 7°（灾害性）｜橙 5–6°（灾害性）｜黄 3–4°（告知性）｜蓝 < 3°（告知性）**。高楼层有放大效应，震感可能更明显。
